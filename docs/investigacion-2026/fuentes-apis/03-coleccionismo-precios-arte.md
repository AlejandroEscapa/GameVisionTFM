# Dimension 03: Coleccionismo, precios, arte y "pro"

## Current State

GameVision es una app Android de tracking de videojuegos que ya integra **HowLongToBeat** (duraciones) como fuente externa. El objetivo de esta dimensión es el salto "ultra pro": **valor de colección física**, **alertas de ofertas de la wishlist**, **arte de calidad para la ficha** y, opcionalmente, **espectadores en vivo**. La monetización futura (que condiciona qué se puede usar) lo cambia todo: varios servicios (IGDB, PriceCharting) distinguen entre uso personal/no comercial y uso comercial.

Resumen ejecutivo de lo investigado (evidencia en la tabla):

- **Precios de juegos físicos**: hay exactamente dos vías "serias": **PriceCharting** (de pago, datos actuales por condición, **sin histórico**, licencia solo para uso interno salvo acuerdo comercial) y **eBay Marketplace Insights** (ventas reales de los últimos 90 días, pero es un API "Limited Release" aprobada por unidades de negocio de eBay). "Video Game Price Charts (VGPC)" ya no existe como servicio aparte: su dominio redirige a PriceCharting (verificado hoy).
- **Ofertas digitales**: **CheapShark** (completamente gratis, sin key, condición: usar sus enlaces de redirect) e **IsThereAnyDeal** (registro de app, límites por ventana de 5 min, comercial permitido si la app es pública, webhooks para usuarios). **GG.deals**: no se pudo verificar API pública (bloquea accesos automatizados, 403).
- **Arte**: **SteamGridDB** (API v2, key gratuita por usuario) e **IGDB artworks** (gratis solo para uso no comercial) cubren de sobra las necesidades de una "ficha espectacular".
- **Live/streaming**: **Twitch Helix "Get Streams"** devuelve `viewer_count` por juego; requiere app Twitch + app access token; bucket de **800 puntos/minuto**. Mapeo directo con IGDB (`game_id`) por ser el mismo dueño (Twitch).
- **Merchandising**: no existe API oficial de merch de videojuegos. Alternativas reales: afiliación **Amazon (PA-API → nueva Creators API**, exige Asociados con ventas reales) o print-on-demand (**Printful**, técnicamente viable pero sin encaje de producto). **MyFigureCollection no tiene API** (y el sitio se opone explícitamente a bots/IA). **Limited Run**: sin API encontrada.
- **Otros "pro"**: **ProtonDB** tiene un endpoint JSON funcional pero **no documentado** (uso frágil); **Steam** no expone API pública de cromos (solo interfaces de economía restringidas a partners); **GOG/Epic** no ofrecen API pública de catálogo para terceros; **Discord Rich Presence** existe vía SDK para juegos propios/Activities, no como fuente de datos para una app ajena.
- **Apps de referencia**: **Discogs** (vinilos) = colección + wantlist + valoraciones de mercado vía API (60 req/min); **CLZ Games** = escaneo de códigos de barras + valores de mercado vía **PriceCharting**, con modelo de suscripción. CLZ demuestra que la combinación "escanea tu estantería → valor total" es un negocio real de pago.

Nota metodológica: los datos provienen de documentación oficial de cada servicio (varias veces vía copia archivada cuando el sitio original bloquea scraping); cuando no se encontró un dato (p. ej., el precio exacto de la suscripción de PriceCharting), se dice expresamente y no se inventa.

## Oportunidades para GameVision

**Adoptar ahora (coste cero o mínimo, valor directo):**

- **SteamGridDB** → *Función*: packs de arte para una "ficha espectacular" (grid vertical, hero, logo, icono) + selector de arte alternativo por juego, como hacen los launchers. *Veredicto*: **adoptar ahora**. Key gratuita por usuario; pedir/atribuir SteamGridDB; cuidado: condiciones comerciales no declaradas en el spec → revisar Terms del sitio antes de monetizar.
- **CheapShark** → *Función*: sección "Ofertas" para juegos de PC + alerta de oferta de la wishlist (endpoint de Alerts email+gameID+precio, o comprobación propia). *Veredicto*: **adoptar ahora** cumpliendo reglas: User-Agent identificable con contacto, llamadas interactivas, caché ligera, **usar siempre `cheapshark.com/redirect?dealID=...`** al enviar al usuario a la tienda.
- **IGDB (si no se usa ya para arte)** → *Función*: portadas/artworks + metadata de alta calidad para la ficha; base del mapeo con Twitch. *Veredicto*: **adoptar ahora**, pero **planificar el salto a "commercial partnership"** en cuanto GameVision monetice (el grant gratuito es solo no comercial).
- **ProtonDB (endpoint no documentado)** → *Función*: badge "Steam Deck / Proton: Gold-Platinum" en la ficha, con cacheado agresivo. *Veredicto*: **adoptar ahora con cautela** ("best effort", jamás bloqueante; no es API soportada).

**Adoptar después (condicionado a monetización, suscripción o registro):**

- **PriceCharting** → *Función*: valor de colección por condición (suelto/CIB/nuevo/gradado), campo de ID PriceCharting en la ficha y **"valor total de mi estantería"** (el feature killer tipo CLZ). *Veredicto*: **después / condicionado**: exige suscripción de pago + **licencia comercial escrita** para mostrar datos a usuarios + purga al terminar + sin histórico. Puente provisional: enlaces externos (linkback a la página del producto), que es justo lo que ellos prefieren.
- **IsThereAnyDeal** → *Función*: alertas de oferta multi-tienda desde la wishlist con **histórico de precios** y **webhooks** (mejor que CheapShark para "avisadme"). *Veredicto*: **adoptar después** de registrar la app; condiciones comerciales aceptables si la app es pública.
- **Twitch Helix** → *Función*: chip "🔴 N espectadores en vivo" y lista de streams para el juego de la ficha. *Veredicto*: **después** (nice-to-have; coste de polling y cobertura limitada en juegos retro/single-player; mapear vía IGDB `game_id`).
- **Amazon Creators API** → *Función*: sección "Merch de este juego" (figuras, camisetas, guías) con enlaces de afiliado. *Veredicto*: **después**: requiere crear Amazon Associates y generar **ventas cualificadas** antes de obtener credenciales (huevo-gallina); PA-API antigua ya está deprecada.

**Descartar (por ahora):**

- **eBay Marketplace Insights** → comps reales de 90 días, pero es limited release "aprobada por unidades de negocio" — inalcanzable realista para una app indie. *Descartar ahora*; alternativa: enlaces a búsquedas "sold" de eBay sin integrar datos.
- **Printful** → POD genérico sin encaje de catálogo de juegos; implicaría logística/precios/impuestos propios. *Descartar* salvo que algún día se venda merch propio diseñado.
- **MyFigureCollection** → sin API y con oposición explícita a automatización. *Descartar*; como mucho, enlaces.
- **Steam Trading Cards** → sin API pública. *Descartar* (máximo, enlaces a inventario web).
- **GG.deals** → sin API verificable; no depender de ello. *Descartar* (revisar en el futuro).
- **GOG / Epic** → sin API pública de catálogo para terceros. *Descartar* por ahora.
- **HowLongToBeat** → ya integrado; sin API oficial, mantener el enfoque actual (no cambiarlo).

**Inspiración de producto (no integración):** Discogs y CLZ Games validan dos ideas: (a) escanear código de barras y (b) mostrar "valor de tu colección" con suscripción. GameVision puede copiar el flujo con **scan UPC → ID PriceCharting/eBay → valor por condición**, y una vista "Mi estantería vale X" — siempre que se resuelva la licencia de datos.

## Tensions & Counter-arguments

- **El feature estrella es el más caro y con más letra pequeña.** "Valor de colección" depende de PriceCharting, cuyo licenciamiento es "internal use only" fuera de acuerdo comercial, obliga a purgar datos al cancelar y **no ofrece histórico** ("Historic prices and historic sales are not supported"). Un gráfico de evolución del valor **no se puede** hacer con su API: habría que construir una serie temporal propia desde el día 1 (cacheando nuestras propias consultas), con los límites de 1 req/s.
- **El atajo del scraping no es una estrategia.** Existen scrapers (p. ej. Apify, desde ~4,99 $/1.000 resultados) y wrappers no oficiales, pero son frágiles, contra los ToS de varios servicios y un riesgo legal/reputacional para un producto que quiere monetizarse. Mejor aceptar el coste de las licencias o postergar el feature.
- **El dato oficial de "vendidos" (eBay) es inaccesible de facto.** Marketplace Insights está tras aprobación de negocio y whitelisting de categorías; para una app pequeña la vía realista es PriceCharting (pago) + enlaces. Argumento a favor de diferir esta función a una fase con ingresos.
- **"Ofertas gratis" tiene contraprestación.** CheapShark es gratis pero exige usar sus redirects y prohíbe construir catálogos cacheados (con riesgo de bloqueo permanente); ITAD añade registro, límite 1000 req/5 min, aprobación por endpoint y una ToS peculiar ("provided in good faith"). Diseñar la app alrededor de consultas interactivas y webhooks, no de crawlers.
- **Arte: barato hoy, preguntas mañana.** SteamGridDB no declara condiciones comerciales ni rate limit en su OpenAPI; IGDB es gratis solo si no hay monetización. Al monetizar, hay que presupuestar (IGDB partnership) y revisar licencias del arte subido por la comunidad (riesgo de imágenes con copyright de terceros).
- **Live es vistoso pero flojo en cobertura.** `viewer_count` fluctúa, exige token de app y polling; para juegos retro/single-player el chip quedará vacío casi siempre. Coste/beneficio cuestionable frente a otras features "pro".
- **Merch: veredicto honesto = enlaces o nada.** No hay APIs de merch oficial del sector; Amazon exige ventas previas (huevo-gallina) y MFC está cerrado (noai/noimageai). Cualquier sección de merchandising será "enlaces de afiliado manuales" como máximo.
- **Fragmentación de IDs.** PriceCharting ID ≠ IGDB id ≠ Twitch game_id ≠ Steam appid ≠ barcode. Sin una tabla de mapeo interna, las features "pro" se rompen en los bordes (juego no encontrado en X). Es trabajo de datos, no solo de API.
- **Privacidad/RGPD en alertas.** La API de Alerts de CheapShark funciona con email del usuario enviado a CheapShark; preferible notificar desde GameVision (polling/ITAD webhooks) y pedir consentimiento explícito si se usan servicios de terceros.
